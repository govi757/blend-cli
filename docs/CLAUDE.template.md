# CLAUDE.md

This project is generated by **blend-cli** (package `blend-kit`), a spec-driven code generator.
The source of truth is the spec files. Most code under `module/` is generated from them.
Before you change generated code, check whether the change belongs in a spec.

## Project layout

```
<project>/                       # folder name MUST equal the .basic file name
├── <project>.basic              # top-level spec: sections and their modules
├── spec/<section>/
│   ├── data/<Name>.data         # shared data classes
│   ├── mongo/<Name>.mongo       # Mongoose collections
│   ├── api/<Name>.express       # API endpoints
│   └── frontend/<Name>.react    # React web app (Vite)
│       frontend/<Name>.rn       # React Native app
├── .basicConfig/*.json          # parsed specs. Generated, never edit by hand.
└── module/<section>/            # generated code
    ├── data/<DataModule>.ts
    ├── express/<section>-api/   # ONE Express server per section (all express-modules merge here)
    ├── react/<ReactModule>/
    └── react-native/<RnModule>/
```

## Commands (always run from the project root)

The CLI finds `<current-folder-name>.basic` in the current directory. It fails anywhere else.

| When you changed…           | Run                                   |
|-----------------------------|---------------------------------------|
| `<project>.basic`           | `blend-cli chop`, then `blend-cli prepare` |
| any file in `spec/`         | `blend-cli prepare`                   |
| then, to regenerate code    | `blend-cli serve`                     |

- `chop` parses `.basic` into `.basicConfig/basicConfig.json`. `prepare` reads that file, so run `chop` first.
- `prepare` creates an empty spec file (`module <Name>`) for each new module, validates every spec and writes `.basicConfig/{data,api,mongo,react,rn}Config.json`. Syntax errors show up as a `syntaxErrors` array with `Line L:C - message` entries. Fix them before you run `serve`.
- The first `serve` for a new React or RN module scaffolds the app (`npm create vite`, `@react-native-community/cli init`, `npm install`, `npx shadcn init`). It is slow, needs network access and may prompt for input. Tell the user before you run it.

## What `serve` overwrites (important)

**Rewritten on every `serve`. Don't edit these. Change the spec instead:**
- anything under a `src-gen/` folder:
  - Express: `module/<s>/express/<s>-api/src-gen/` (`api-interfaces/`, `api-data/`, `api-routes/`, `data/`, `models/`)
  - React: `module/<s>/react/<M>/src/src-gen/` (`data/`, `redux/`, `router/blend-router.tsx`, `component/MDP.ts`, `component/mdpHook.ts`)
  - RN: `module/<s>/react-native/<M>/src-gen/` (`data/`, `redux/`, `router/config/*LayoutConfig.tsx`, `component/`)
- `module/<s>/data/*.ts`

**Created once and never overwritten. Hand-written logic goes here:**
- Express services: `src/services/<ExpressModule>/<ApiSection>/<ApiSection>.service.ts`. Each one is a class that `implements I<ApiSection>Api`. Fill in the method bodies.
- Express scaffolding: `src/app.ts`, `src/middlewares/auth.ts`, `src/routes/common/common.routes.config.ts`, `src/routes/swaggerConfig.ts`, `package.json`, `tsconfig.json`, `.env.dev`
- Screens: `src/view/<under-path>/<Screen>.tsx`
- Components: `src/component/<under-path>/<Name>/{<Name>.tsx, <Name>MDP.ts, index.ts}`
- Layouts: `src/layout/<Layout>Layout.tsx`

Two consequences:
1. If you add a method to an API section after its service file exists, the regenerated interface requires the method, but the CLI won't add it to the service. Add the method to the service by hand, using the signature from `src-gen/api-interfaces/...`.
2. If you rename or remove something in a spec, the old generated files are not deleted. Remove stale files yourself.

## Spec syntax

General rules:
- Module, data, collection, API-section, component, screen and layout names are **PascalCase**. Field and API names are **camelCase**.
- Every spec file begins with `module <Name>`, and `<Name>` must match the module declared in `.basic`.
- Paths are double-quoted.

### `<project>.basic`
```
section shop {
  data-module Catalog, Orders
  mongo-module ShopDb
  express-module Products
  react-module ShopWeb
  rn-module ShopMobile
}
```
A module can only reference modules in the **same section**. The section name becomes the folder name and the API project name (`shop-api`).

### `.data`
```
module Catalog
data Category(id: string, name: string)
data Product(id: string, price: number, tags: string[], discount: number?, category: Category)
```
Types: `string | number | boolean | any`, another data class in the module, plus a `[]` or `?` suffix.

### `.mongo`
```
module ShopDb
collection Product {
  property title: String (index),
  property sku: String (unique, index),
  property releasedAt: Date?,
  reference category: Category
}
```
- Types: `String | Number | Boolean | Date | Object | Mixed | any`, plus `[]` or `?`.
- A collection needs at least one `property`. All `reference` lines must come **after** all `property` lines. Entries are comma-separated.
- Generated output goes to `src-gen/models/<ExpressModule>/<MongoModule>/`, with a `Database.ts` next to it.

### `.express`
```
module Products
section Product {
  api getProduct(GET) {
    input(id: string)
    output(product: Catalog->Product)
  }
  api listProducts(GET) { output(Catalog->Product[]) }
  api createProduct(POST) {
    authenticated
    input(product: Catalog->Product)
    output(id: string)
  }
}
```
- Methods: `GET | POST | PUT | DELETE`. Inside an `api` block the order is fixed: `authenticated`, then `input(...)`, then `output(...)`, and each one is optional.
- Types: `string | number | boolean | any | object`, or `DataModule->DataName`, each with an optional `[]` or `?`.
- `output(...)` takes either named fields or one bare type.
- `authenticated` adds JWT `verifyToken`, and the service method receives `currentUser` as its first argument.
- Generated input classes are named `<SECTION>_<API>_INPUT` (upper-case) in `src-gen/api-data/...`.
- The same specs also generate the Redux Toolkit and redux-saga API client (slice, actions, saga) in every React and RN module of the section.

### `.react`
```
module ShopWeb
component ProductCard, PriceTag under "catalog"
screen ProductList, ProductDetail under "catalog"
layout Main("/") {
  page Products("products") view(ProductList)
  page Product("products/:id") view(ProductDetail)
  layout Account("account") { page Profile("profile") view(ProductList) }
}
```
The order is fixed: all `component` lines, then all `screen` lines, then the layouts. Inside a layout, pages come before nested layouts. `view(...)` must name a declared screen.

### `.rn`
This works like `.react`, but each layout also needs `type(Stack)` or `type(Drawer)`:
```
layout Root("root") type(Stack) { page Products("products") view(ProductList) }
```
RN paths can't be empty and can't contain `:`. Use only `[a-zA-Z0-9_/]`.

## Express app gotchas

- `src/app.ts` is generated once with a placeholder route import (`../src-gen/api-routes/BaskyApi/User.routes`). **You register routes by hand.** For each API section, import `src-gen/api-routes/<ExpressModule>/<ApiSection>.routes` and add `routes.push(new <ApiSection>Routes(app))`. Remove the placeholder if that file doesn't exist.
- The server runs on port 8000, with Swagger at `/api-docs`. Env is loaded from `.env.<NODE_ENV|dev>`, and it needs `MONGO_DB_URL` and `JWT_SECRET_KEY`.
- To run it: `cd module/<s>/express/<s>-api && npm install && npm start`.

## Working rules for Claude

1. Feature requests (a new endpoint, field, collection, screen or route) start with a **spec edit**. Then run `prepare` and fix any syntax errors, then run `serve`. Fill in the hand-written logic last.
2. Never edit `src-gen/`, `module/<s>/data/` or `.basicConfig/`. Your edits there will be lost.
3. After `serve`, run the type-checker in the affected app (`npx tsc --noEmit`) to catch services that no longer match their regenerated interfaces.
4. Ask before running the first `serve` that scaffolds a new React or RN app. It installs packages and can take minutes.
5. When a spec fails to parse, check it against the exact grammar in the appendix below. The grammar is the final word; the examples above only illustrate it.

## Appendix: spec grammars (ANTLR4)

These are the exact grammars blend-cli uses to parse each spec type. Some notes on reading them:
- Quoted strings are literal keywords and symbols.
- `?` means optional, `*` means zero or more, `+` means one or more.
- Whitespace and newlines are ignored everywhere.
- There is **no comment syntax**. Don't put `//` or `#` comments in spec files.
- Tokens such as `'input('` and `'output('` have no space inside. `input (` will not parse.

### `.mongo` (BlendMongo.g4)
```antlr
program: moduleDefinition collectionDefinition+;

moduleDefinition: 'module' CAPITAL_IDENTIFIER;

collectionDefinition: 'collection' CAPITAL_IDENTIFIER '{' property (',' property)*  (',' reference (',' reference)*)? '}';

property:'property' IDENTIFIER ':' type propertyChars?;
propertyChars: '(' mongoChars (',' mongoChars)* ')';
reference: 'reference' IDENTIFIER ':' CAPITAL_IDENTIFIER propertyChars?;
mongoChars: 'unique' | 'index';

type: baseType
    | baseType '[]'
    | baseType '?';

baseType: primitiveType;

primitiveType: 'String' | 'Number' | 'Boolean' | 'any' | 'Object' | 'Date'|'Mixed';

IDENTIFIER: [a-z_][a-zA-Z0-9_]*;
CAPITAL_IDENTIFIER: [A-Z][a-zA-Z0-9_]*;
WS: [ \t\r\n]+ -> skip;
```

### `.express` API spec (BlendApi.g4)
```antlr
program: moduleDefinition sectionDefinition*;
sectionDefinition: 'section' CAPITAL_IDENTIFIER '{' apiDefinition* '}';
moduleDefinition: 'module' CAPITAL_IDENTIFIER;
apiDefinition: 'api' IDENTIFIER '(' HTTP_METHOD ')' '{' authenticated? inputDefinition? outputDefinition? '}';

authenticated: 'authenticated';
inputDefinition: 'input(' field (',' field)* ')';
outputDefinition: 'output(' field (',' field)* ')' | 'output(' directOutputDefenition ')';
directOutputDefenition: type;

field: IDENTIFIER ':' type;
type: primitiveType
    | primitiveType '[]'
    | primitiveType '?'
    | CAPITAL_IDENTIFIER '->' CAPITAL_IDENTIFIER
    | CAPITAL_IDENTIFIER '->' CAPITAL_IDENTIFIER '?'
    | CAPITAL_IDENTIFIER '->' CAPITAL_IDENTIFIER '[]';

primitiveType: 'string' | 'number' | 'boolean' | 'any' | 'object';

HTTP_METHOD: 'GET' | 'POST'|'DELETE' | 'PUT';
IDENTIFIER: [a-z_][a-zA-Z0-9_]*;
CAPITAL_IDENTIFIER: [A-Z][a-zA-Z0-9_]*;
WS: [ \t\r\n]+ -> skip;
```
Notes:
- `primitiveType[]?` (array **and** optional) is not allowed.
- In `X->Y`, `X` is a data module and `Y` is a data class inside it.

### `.data` (BlendData.g4)
```antlr
program: moduleDefinition dataDefinition+ EOF;

moduleDefinition: 'module' CAPITAL_IDENTIFIER;

dataDefinition: 'data' CAPITAL_IDENTIFIER '(' field (',' field)* ')';

field: IDENTIFIER ':' type;

type: baseType
    | baseType '[]'
    | baseType '?'
    | baseType '->' baseType
    | baseType '->' baseType '?'
    | baseType '->' baseType '[]';

baseType: primitiveType | CAPITAL_IDENTIFIER;

primitiveType: 'string' | 'number' | 'boolean' | 'any';

IDENTIFIER: [a-z_][a-zA-Z0-9_]*;
CAPITAL_IDENTIFIER: [A-Z][a-zA-Z0-9_]*;
WS: [ \t\r\n]+ -> skip;
```
Notes:
- A `.data` file needs at least one `data` definition, because the rule is `dataDefinition+`. A file that only contains `module X` fails here.
- `object` is **not** a valid type in `.data` (it is valid in `.express`).

### `.react` (BlendReact.g4)
```antlr
program: moduleDefinition componentDefenition* screenDefenition* layoutDefinition*;

moduleDefinition: 'module' CAPITAL_IDENTIFIER;

screenDefenition: 'screen' CAPITAL_IDENTIFIER (',' CAPITAL_IDENTIFIER)* 'under' PATH_IDENTIFIER ;
componentDefenition: 'component' CAPITAL_IDENTIFIER (',' CAPITAL_IDENTIFIER)* 'under' PATH_IDENTIFIER ;

layoutDefinition: 'layout' CAPITAL_IDENTIFIER '(' PATH_IDENTIFIER ')' '{' pageDefinition* layoutDefinition* '}';
pageDefinition: 'page' CAPITAL_IDENTIFIER '(' PATH_IDENTIFIER ')' 'view' '(' CAPITAL_IDENTIFIER ')';

PATH_IDENTIFIER: '"' [a-zA-Z0-9_/:]* '"';
IDENTIFIER: [a-z_][a-zA-Z0-9_]*;
CAPITAL_IDENTIFIER: [A-Z][a-zA-Z0-9_]*;
WS: [ \t\r\n]+ -> skip;
```
Notes:
- Paths can use letters, digits, `_`, `/` and `:` only. `-`, `.` and spaces are **not** allowed, so `"user-profile"` fails.
- An empty path `""` is allowed.
